# Founder Operating System

> The practical daily workflow that integrates all 14 business frameworks into how you actually work.

> **NEW to this entire playbook?** [**→ GETTING STARTED GUIDE**](../GETTING-STARTED.md) **←** (30 min complete onboarding)

## What This Is

You have 14 excellent business frameworks. The Founder OS is the **system** that helps you use them effectively:

- **Daily Priority Protocol** - Focus on what matters (10 min/day)
- **Weekly Review System** - Honest progress assessment (45 min/week)
- **Monthly Strategic Review** - Course correction (2 hours/month)
- **Decision Maker** - Framework-driven choices
- **Anti-Pattern Detector** - Catch classic mistakes
- **Metrics Dashboard** - Track only what matters

## Quick Start (30 minutes)

1. Read [`quick-start.md`](quick-start.md)
2. Identify your stage (Problem / Solution / Business Model / Growth)
3. Set your two metrics
4. Write tomorrow's SMIT (Single Most Important Task)
5. Do it

That's it. Everything else is just scaffolding.

## How It Works

### The Daily Loop (10 minutes)

Every morning:
1. What stage am I in?
2. What's the one bottleneck?
3. What's today's SMIT?

Do the SMIT. Ignore everything else.

### The Weekly Loop (45 minutes)

Every Friday:
1. What were the numbers this week?
2. Framework health check (using which framework)
3. Plan next week's priorities

### The Monthly Loop (2 hours)

First Friday of each month:
1. Brutal honesty about progress
2. Stage assessment (stay / move / pivot / kill)
3. Framework scoring (which need work)
4. Next month's plan

## Integration with 14 Frameworks

The OS tells you **when** to use each framework:

```
Daily Standup → Identifies constraint
     ↓
Diagnose Skill → Routes to right framework  
     ↓
Framework Skills → Gives detailed method
(mom-test, lean-startup, traction, etc.)
     ↓
Back to Daily Standup → Apply what you learned
```

**Monday:**

### Traditional Advice

- Use: `quick-start.md`

- Focus: Problem validation

### Have an Idea, No Customers (Month 1-3)
- Use: `templates/daily-standup.md` + `customer-conversation-tracker.md`
- Use frameworks: mom-test, four-steps, obviously-awesome
- Focus: Solution validation

### Have Customers, Can't Scale (Month 3-6)
- Use: All templates
- Use frameworks: traction, 100m-leads, lean-startup
- Focus: Business model validation

### Growing But Chaotic (Month 6+)
- Use: Monthly strategic reviews
- Use frameworks: crossing-the-chasm, blue-ocean-strategy
- Focus: Sustainable growth

## The One Rule

**Work on the constraint, not around it.**

If your constraint is customer access:
- ✅ Outreach, channel testing, distribution
- ❌ Building features, perfecting website

If your constraint is messaging:
- ✅ Rewriting copy, 5-second tests, positioning
- ❌ Adding features, backend optimization

If your constraint is pricing:
- ✅ WTP conversations, packaging, testing models
- ❌ Marketing campaigns, new integrations

Everything else is avoidance.

## Success Metrics

You're using the OS correctly if:

- [ ] You complete 3-5 SMITs per week
- [ ] Your 2 core metrics improve week-over-week
- [ ] You catch anti-patterns before they hurt
- [ ] You make framework-informed decisions
- [ ] You feel focused (not overwhelmed)

You're NOT using it correctly if:

- [ ] You're tracking 10+ metrics
- [ ] You're using 5 frameworks simultaneously
- [ ] Templates take more time than they save
- [ ] You're "doing the system" but metrics aren't improving
- [ ] You're filling out templates instead of talking to customers

**If second list applies:** Stop. Read the "Honesty Rule" section in `SKILL.md`.

## Common Mistakes

### Week 1
❌ Trying to use all 14 frameworks at once  
✅ Pick 1-2 frameworks for the week

❌ Tracking everything  
✅ Track only 2 metrics for your stage

❌ Vague SMITs ("work on marketing")  
✅ Specific SMITs ("send 20 DMs to [segment]")

### Month 1
❌ Skipping weekly reviews  
✅ Block 45 min every Friday (non-negotiable)

❌ Setting easy SMITs to guarantee completion  
✅ Set SMITs that directly address the constraint

❌ Not using the actual frameworks  
✅ Each SMIT should reference a framework file

### Month 3
❌ Gaming the metrics to look good  
✅ Brutal honesty in monthly reviews

❌ Avoiding hard decisions  
✅ Use decision log for significant choices

❌ Working hard but directionless  
✅ Re-run diagnose skill to realign

## When the OS Isn't Helping

The system works **when you use it honestly**.

### Signs it's working:
- Making faster progress
- More focused
- Catching mistakes earlier
- Better decisions

### Signs it's not working:
- Doing system instead of real work
- Filling out templates instead of talking to customers
- Busy but metrics not improving
- System takes more time than it saves

**If not working:** Read the meta-rules in `SKILL.md`. You're probably:
1. Tracking wrong things
2. In wrong stage
3. Using wrong frameworks
4. Not being honest with yourself

## Integration with Other Tools

### Works Great With:
- Claude Code / ChatGPT (load framework skills as context)
- Notion / Obsidian (store weekly/monthly reviews)
- Spreadsheets (track metrics over time)
- Calendar blocks (protect SMIT time)

### Doesn't Replace:
- Talking to customers (do more, not less)
- Building product (frameworks inform, don't replace building)
- Making hard decisions (frameworks help, you decide)
- Your own judgment (trust gut when it contradicts framework)

## Questions?

**"Do I need to read all 14 framework skills first?"**  
No. Start with diagnose skill - it routes you to the right one.

**"Can I skip daily standups?"**  
You can, but then you'll be unfocused and the system won't help you.

**"What if my situation doesn't fit any framework?"**  
Then stop using frameworks. Go talk to customers. Come back when you have clarity.

**"How long until I see results?"**  
Week 1: More focused  
Week 4: Clear patterns emerging  
Month 3: Measurable progress  
Month 6: System is invisible (just how you work)

**"Can I customize templates?"**  
Yes, but use as-written for 1 month first. Then adapt based on what actually helps.
