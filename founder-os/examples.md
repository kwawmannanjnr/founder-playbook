## Example 1: Solo Founder, Week 1

**Context:** Sarah has an idea for a project management tool for design agencies. She's been thinking about it for 3 months but hasn't talked to anyone.

### Day 1 - Monday

**Daily Standup:**
```
Stage: Problem Validation
Constraint: Don't know if design agencies actually have this problem
SMIT: Have 5 mom-test conversations with design agency owners/PMs
Done when: Completed 5 conversations, documented their answers
Framework: mom-test
Time budget: 4 hours
```

**What happened:**
- Sent 20 DMs on Twitter to design agency owners
- Got 7 responses
- Scheduled 5 calls for this week
- Completed 2 calls

**Evening check:** ✅ 2/5 done, on track for this week

---

### Day 2 - Tuesday

**Daily Standup:**
```
Stage: Problem Validation
Constraint: Same - validating if problem exists
SMIT: Complete remaining 3 mom-test conversations + document patterns
Done when: 5 conversations documented in customer-conversation-tracker.md
Framework: mom-test
Time budget: 3 hours
```

**What happened:**
- Completed 3 more calls
- Used mom-test questions: "Tell me about last time project got derailed..."
- Noticed pattern: 4 out of 5 mentioned same issue (client feedback scattered across email/Slack/comments)

**Evening check:** ✅ Done. Pattern emerging: feedback consolidation is real pain.

---

### Day 3 - Wednesday

**Daily Standup:**
```
Stage: Problem Validation (still)
Constraint: Need to know if this pain is expensive enough to pay for
SMIT: Score the 5 people using four-steps earlyvangelist hierarchy
Done when: Each person scored on 5 criteria, know who to focus on
Framework: four-steps
Time budget: 2 hours
```

**What happened:**
- Scored all 5 people:
  - Person 1: 42/50 (strong earlyvangelist)
  - Person 2: 38/50 (strong)
  - Person 3: 22/50 (polite interest only)
  - Person 4: 35/50 (decent)
  - Person 5: 19/50 (wrong segment)

**Learning:** 2-3 strong earlyvangelists is good signal. Should focus on agencies with >10 person teams (they have the pain most).

**Evening check:** ✅ Done. Know who to build for.

---

### Day 4 - Thursday

**Daily Standup:**
```
Stage: Problem Validation → Moving to Solution Validation
Constraint: Need to know if they'll pay before building
SMIT: Ask top 2 earlyvangelists: "If this existed, what would it be worth?"
Done when: Had WTP conversations, know price range
Framework: monetizing-innovation
Time budget: 2 hours
```

**What happened:**
- Called Person 1 and Person 2
- Used WTP script: "What are you spending now on project management tools?"
  - Person 1: $200/mo (Asana + Notion + Loom)
  - Person 2: $150/mo (Monday.com + Slack)
- Asked: "If this consolidated feedback and reduced revision cycles, what would that be worth?"
  - Person 1: "If it saved us 1 revision per project, that's 10 hours of designer time. Worth $500-1000/mo easy."
  - Person 2: "We lose clients when feedback process sucks. Worth $200-300/mo."

**Learning:** Price ceiling is higher than expected. Should think $200-500/mo range, not $50/mo.

**Evening check:** ✅ Done. Validated willingness to pay.

---

### Day 5 - Friday

**Daily Standup:**
```
Stage: Moving to Solution Validation
Constraint: Need clear positioning before building anything
SMIT: Complete obviously-awesome 5+1 positioning worksheet
Done when: Can articulate what we are, who it's for, what alternative it replaces
Framework: obviously-awesome
Time budget: 3 hours
```

**What happened:**
- Worked through positioning:
  - Competitive alternatives: Using Asana + email + Slack + spreadsheets
  - Unique attributes: One place for all client feedback with design-specific context
  - Value: Reduce revision cycles, happier clients
  - Target customers: Design agencies with >10 people and recurring clients
  - Market category: Client feedback management (not "project management")
  - Trends: Remote work = more scattered feedback

**Positioning statement:** "We're client feedback management for design agencies - consolidate all client input from email/Slack/meetings into one place with design context, so you reduce revision cycles."

**Evening check:** ✅ Done. Clarity on positioning.

---

**Weekly Review:**

```
Stage: Problem Validation → Solution Validation
Primary metric: Conversations completed: 5/10 target (good start)
Secondary metric: 80% described pain with emotion (4/5 people)

SMITs completed: 5/5 ✅

Best insight: 
Price ceiling is much higher than expected ($200-500/mo vs $50/mo). 
These agencies lose clients over bad feedback processes.

Pattern:
>10 person agencies with recurring clients have most pain.
Smaller agencies manage with spreadsheets.

Next week constraint: Need to validate if agencies will pay BEFORE I build
Next week plan:
1. Create simple pitch deck showing the concept
2. Ask Person 1 and Person 2 for $500 pre-order to build custom solution
3. If 2+ say yes → build MVP
4. If 0-1 say yes → dig deeper into why not
```

## Example 2: Technical Founder, Pivoting

**Context:** Mike built a "content scheduler for everyone" - has 200 signups, 2 paying customers after 3 months. Both paying customers are B2B SaaS founders using it for LinkedIn. Considering pivot.

### Monthly Strategic Review - Month 3

**Brutal Honesty:**
```
Goal last month: Get to 10 paying customers
Actual: Got to 2 paying customers
Gap: We're 8 short, and growth has flatlined

Founder honesty check:
- Working on constraint? 4/10 (I've been adding features instead of selling)
- Measuring reality? 6/10 (Celebrating signups, ignoring conversion rate)
- Talking to customers? 5/10 (Only talked to 3 people all month)
- Making decisions? 3/10 (Avoiding the "should we pivot?" decision)
```

**Stage Assessment:**
```
Where I think we are: Solution Validation
How long: 3 months
Evidence we should move forward: None. 2 customers isn't 10.
Evidence we're not ready: 
- Trial-to-paid conversion: 1% (terrible)
- Nobody can explain what we do clearly
- The 2 paying customers are using it for ONE specific use case (LinkedIn for founders)

Honest call: PIVOT (Customer Segment + Use Case)
Reasoning: 
- Pattern of 2 (both B2B SaaS founders, both LinkedIn)
- They're in same segment doing same job-to-be-done
- Head-to-Head positioning in "content scheduling" is losing
- Need to go vertical
```

**Framework Health Check:**
```
Obviously Awesome: 3/10 - I'm positioned in a crowded category
Lean Startup: 4/10 - Should've pivoted 1 month ago based on data
Mom Test: 6/10 - The conversations I did have were good
Four Steps: 5/10 - Didn't identify earlyvangelist profile clearly enough
```

**Decision Using Lean Startup Pivot Catalog:**
```
Pivot Type: Customer Segment Pivot
- Keep: Same product (content scheduling)
- Change: Target segment (B2B SaaS founders) and positioning (LinkedIn engine)

New positioning (using Obviously Awesome):
- Competitive alternatives: Manual LinkedIn posting + hiring VA + random tools
- Unique attributes: Understands B2B SaaS founder content strategy specifically
- Value: Consistent LinkedIn presence = lead gen channel without full-time effort
- Target: B2B SaaS founders doing <$1M ARR (still grinding on distribution)
- Category: LinkedIn content engine (not "content scheduler")
```

---

### Week 1 After Pivot - Monday

**Daily Standup:**
```
Stage: Solution Validation (restarting)
Constraint: Need to validate B2B SaaS founders will pay for LinkedIn-specific tool
SMIT: Rewrite homepage using storybrand BrandScript for new segment
Done when: New homepage live, focused on B2B SaaS founders + LinkedIn
Framework: storybrand
Time budget: 4 hours
```

**What happened:**
- Used StoryBrand BrandScript:
  - Character: B2B SaaS founder
  - Problem: Inconsistent on LinkedIn, losing lead gen opportunity
  - Guide: We get it, we're founders too
  - Plan: 1) Import your content ideas 2) We optimize for LinkedIn 3) You post consistently
  - Call to action: "Get your LinkedIn strategy session"
  - Success: LinkedIn becomes your #1 lead channel
  - Failure: Competitors own LinkedIn, you're invisible

- New homepage hero: "Turn LinkedIn into your #1 B2B lead channel - without hiring a full-time content person"

**Evening check:** ✅ Done. 5-second tested with 3 founders - all understood immediately.

---

### Week 1 - Friday

**Daily Standup:**
```
Stage: Solution Validation
Constraint: Need to find B2B SaaS founders fast
SMIT: Test traction Phase I channel - Community Building
Done when: Posted in 5 founder communities, got 10+ conversations started
Framework: traction + 100m-leads
Time budget: 3 hours
```

**What happened:**
- Posted in Indie Hackers, SaaS subreddit, 3 Slack groups
- Gave value first (shared our LinkedIn content framework for free)
- Got 23 replies
- Scheduled 12 calls for next week

**Evening check:** ✅ Done. Distribution is much easier when you're specific.

---

**Weekly Review After Pivot:**
```
Stage: Solution Validation (fresh start)
Primary metric: Paying customers - restarting from 2
Secondary metric: Conversion rate from conversation to trial

Insight: 
Vertical positioning unlocked distribution. 
Got 12 conversations in 1 week vs 5/month before.
People understand "LinkedIn for founders" instantly.

Next week:
Convert 12 conversations → 3-5 trials → 1-2 paid
Using: 100m-offers (make offer irresistible), monetizing-innovation (price it right)
```

## Example 3: Non-Technical Founder, Stuck

**Context:** Jessica wants to build a meal planning app for busy parents. She's been "planning" for 6 months. Hasn't built anything, hasn't talked to anyone.

### Month 1 - Week 1

**Initial Assessment (using Diagnose skill):**

```
Do people want this?
- Have 5 people given you money? NO
- Talked to 10+ potential customers? NO

→ STOP. You are guessing. Use mom-test.
```

**Monday Standup:**
```
Stage: Problem Validation (haven't started)
Constraint: Haven't talked to anyone - just guessing
SMIT: Find and DM 20 busy parents, ask to hear about their meal planning
Done when: Sent 20 DMs, got 5+ responses
Framework: mom-test
Time budget: 2 hours
```

**What happened:**
- Found parents in parenting subreddits who posted about being overwhelmed
- Sent DMs: "Saw your post about [specific struggle]. I'm researching meal planning for a project - can I hear about how you handle it? 15 min call?"
- Got 8 responses
- Scheduled 5 calls

**Learning:** People will talk to you if you ask about THEIR problem, not YOUR idea.

---

**Tuesday-Thursday:**
- Completed 5 mom-test conversations
- Asked: "Walk me through last week's meal planning"
- Asked: "What have you tried?"
- Asked: "What's the worst part?"

**Pattern discovered:**
- 5/5 people said planning isn't the problem
- Actual problem: Kids won't eat what's planned
- They don't need planning app - they need: "meals my kids will actually eat"

**THIS IS A DIFFERENT PROBLEM**

---

**Friday Standup:**
```
Stage: Problem Validation
Constraint: Realized I'm solving the wrong problem
SMIT: Talk to 5 more parents, specifically about picky eating issue
Done when: Confirmed if this is expensive enough to pay for
Framework: mom-test + four-steps
Time budget: 3 hours
```

**What happened:**
- 5 more conversations
- 8/10 parents mentioned picky eating as biggest pain
- 3/10 have spent $200+ on books/courses about picky eating
- 2/10 have hired nutritionists ($500-2000)

**Earlyvangelist score:**
- Have the problem: 8/10
- Know they have it: 8/10
- Actively looking: 3/10 (only the ones spending money)
- Have assembled solution: 2/10 (trying random recipes, tracking in spreadsheets)
- Have budget: 3/10

**Learning:** 
Problem is real and expensive for SOME parents (the 3/10), but not all.
Need to focus on parents who've already spent money trying to solve this.

---

**Weekly Review:**
```
SMITs completed: 4/5 (missed one day)

Biggest learning:
I almost built the wrong product. 
Original idea (meal planning app) ≠ actual problem (picky eating).

Framework that saved me: mom-test
If I'd started building without talking to people, 
I would've wasted 3-6 months.

Next week:
Focus on the 3 parents who've already spent money.
Run WTP conversations - what would they pay?
Explore: is this a productizable solution or do they need coaching?
```

## Example 4: Founder with Customers, Can't Scale

**Context:** Tom has 25 paying customers for a B2B analytics tool ($99/mo each). Growth has flatlined for 2 months. All customers came from his personal network.

### Using Anti-Pattern Detector

**Pattern:** "We Need to Raise Money to Grow"

```
Symptoms:
✅ Growth has stalled
✅ Haven't identified why current channel stopped working
✅ All customers from one channel (personal network)

Diagnosis: Exhausted one channel without finding the next
```

**Fix (using Traction Bullseye Framework):**

---

**Week 1 - Monday:**
```
Stage: Business Model Validation (have customers, need repeatable channel)
Constraint: Only one distribution channel (personal network), now tapped out
SMIT: Brainstorm all 19 traction channels, rank top 5 to test
Done when: Completed Bullseye Framework ranking
Framework: traction
Time budget: 2 hours
```

**Bullseye Brainstorm:**
```
Potentially good channels:
1. Content Marketing (write about analytics insights)
2. Speaking Engagements (talk at industry events)
3. SEO (rank for "analytics for [industry]")
4. Community Building (create analytics community)
5. Partnership (integrate with popular tools)

Test ranking (based on current resources):
Outer ring (maybe later): SEO, Partnership
Middle ring (possible): Community Building, Speaking
Inner ring (test first): Content Marketing

Reasoning: We have domain expertise, can create valuable content fast
```

---

**Week 1 - Tuesday-Thursday:**
```
SMIT: Run Content Marketing test at $250 budget (traction Bullseye test)
Done when: Published 3 high-value posts, measured traffic + leads
Framework: traction + 100m-leads
```

**What happened:**
- Wrote "7 analytics mistakes that cost us $100K" (from real experience)
- Posted on LinkedIn, indie hackers, relevant subreddits
- Got 2,000 views, 45 email signups, 3 demo requests

**Learning:** Content marketing has signal. Should test more.

---

**Week 1 - Friday:**
```
SMIT: Test Speaking Engagements (Phase I unscalable version)
Done when: Pitched 10 local meetups/events, got 1 yes
Framework: traction Phase I
```

**What happened:**
- Emailed 10 meetup organizers
- Offered: "I'll share 7 analytics mistakes that cost real companies $100K+"
- Got 1 yes (local startup meetup next month)
- Got 2 maybes (will follow up)

**Learning:** Speaking has potential but slower cycle than content.

---

**Weekly Review:**
```
Stage: Business Model Validation
Primary metric: CAC for new channels
- Personal network: $0 CAC (tapped out)
- Content marketing test: ~$80 CAC (3 demos from 45 signups, 1 converted)
- Speaking: TBD

Insight:
Content marketing has better CAC than expected.
Personal network worked because of trust - 
content is building trust at scale.

Next week:
Double down on content: publish 5 more posts
Set up SEO test (longer timeline)
Give the speaking talk, measure conversions
```

**After 4 weeks:**
- Content + Speaking became 2 new channels
- Combined: 8 new customers in month 2 (vs 0 in month 1)
- CAC: $120 avg (within LTV/3 target)
- Growth unlocked without fundraising

## Example 5: Framework Integration in Real Decision

**Context:** Lisa is choosing between two directions for her SaaS tool.

**Option A:** Horizontal - "Team collaboration for everyone"  
**Option B:** Vertical - "Team collaboration for architecture firms"

---

**Decision Process:**

### Step 1: Use Obviously Awesome (Positioning)

```
Option A (Horizontal):
- Competitive alternatives: Slack, Teams, Asana, Notion
- Market position: Head-to-Head in VERY crowded category
- Differentiation: Hard to articulate uniquely

Option B (Vertical):
- Competitive alternatives: Generic tools + spreadsheets + email
- Market position: Big Fish in Small Pond (architecture is underserved)
- Differentiation: Clear - built for architecture-specific workflows
```

**Obviously Awesome says:** Option B has better positioning (avoid Head-to-Head)

---

### Step 2: Use Four Steps (Market Size)

```
Option A:
- Market: ~100M knowledge workers
- Addressable: Anyone who collaborates
- Findable: Very hard (too broad)

Option B:
- Market: ~200K architecture firms globally
- Addressable: Firms with >5 people = ~40K
- Findable: Very easy (specific online communities, conferences, publications)
```

**Four Steps says:** Option B more findable (Phase I channels easier)

---

### Step 3: Use Crossing the Chasm (Beachhead)

```
Option A:
- "Everyone" is not a beachhead
- Can't dominate a segment
- Word-of-mouth diffusion: slow (no tight community)

Option B:
- Architecture firms are a tight community
- They talk to each other at conferences
- Word-of-mouth diffusion: fast (bowling pin effect)
```

**Crossing the Chasm says:** Option B can create beachhead

---

### Step 4: Use Traction (Distribution)

```
Option A channels to test:
- Content marketing (competing with huge budgets)
- Ads (expensive, broad targeting)
- SEO (competing with Slack, Notion, etc.)

Option B channels to test:
- Speaking at architecture conferences
- Content marketing in architecture publications  
- Community building in architecture forums
- Partnership with architecture software (AutoCAD, Revit)
```

**Traction says:** Option B has more accessible Phase I channels

---

### Step 5: Use Monetizing Innovation (Pricing)

```
Option A:
- Competing at $10-30/user/mo (standard SaaS pricing)
- No pricing power (commoditized category)

Option B:
- Architecture firms have bigger budgets ($1000s for specialized tools)
- Can charge $50-200/user/mo (premium for vertical)
- Pricing power from specialization
```

**Monetizing Innovation says:** Option B has higher WTP

---

### Decision Log Entry:

```
Decision: Option B - Vertical (architecture firms)

Why:
- Better positioning (5 frameworks aligned)
- Easier to find customers (specific communities)
- Higher pricing power (specialized = premium)
- Faster word-of-mouth (tight community)

What we could be wrong about:
- Architecture market might be smaller than we think
- Architecture-specific features might be hard to build

Reversibility: Moderately reversible
Can pivot to horizontal later if needed, 
but will lose 6 months of vertical focus.

Success criteria:
- 20 architecture firm conversations in 2 weeks
- 60%+ describe workflows we can uniquely solve
- 5 firms willing to pay $100+/user/mo

Review date: 2 weeks
```

## Key Patterns Across All Examples

### Pattern 1: Frameworks Compound

Sarah used:
- mom-test → validated problem
- four-steps → identified earlyvangelists
- monetizing-innovation → validated pricing
- obviously-awesome → clarified positioning

Each framework built on the previous one.

### Pattern 2: Honest Assessment Prevents Waste

Mike almost wasted 3 more months adding features.  
Monthly review forced honest look at metrics → pivot decision → unlocked growth.

Jessica almost built the wrong product entirely.  
Mom-test conversations in Week 1 saved 6 months.

### Pattern 3: Constraints Clarify Action

Tom was stuck "trying to grow."  
Identified specific constraint (distribution) → used Traction → tested new channels → growth resumed.

### Pattern 4: System Catches You

All four founders caught themselves in anti-patterns:
- Sarah almost skipped pricing validation
- Mike delayed obvious pivot for 2 months
- Jessica almost built without talking to customers
- Tom almost tried to raise money instead of fixing distribution

Weekly reviews surfaced the patterns before too much damage.

### Pattern 5: One Framework at a Time

None of these founders used all 14 frameworks at once.

They used 1-2 per week, went deep, made progress, moved on.

**That's the point of the Operating System:**
- Routes you to right framework
- Keeps you focused on one constraint
- Catches you when you drift
- Measures whether it's actually working
